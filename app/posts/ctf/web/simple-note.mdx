### Challenge Analysis
이번 문제는 해당 웹 사이트의 여러 기능 중에서 backup 로직에 존재하는 취약점을 통해  
flag를 얻는 문제예요.

## source code analyze

전체 코드를 보면 이 웹사이트에는 "쓰기, 수정, 삭제, 백업" 기능이 존재해요.  
그 중 backup_notes 함수에 취약점이 존재해요.

 ```python
lock = threading.Lock()
new_note_id = 0
notes = {}

def create_note(content):
    global new_note_id
    with lock:
        note_id = new_note_id
        new_note_id += 1
        notes[note_id] = content
        return notes[note_id]

def read_note(note_id):
    with lock:
        return notes[note_id]

def update_note(note_id, content):
    with lock:
        notes[note_id] = content
        return notes[note_id]

def delete_note(note_id):
    with lock:
        del notes[note_id]

def backup_notes(timestamp):
    with lock:
        with open('./tmp/notes.tmp', 'w') as f:
            f.write(repr(notes))
        subprocess.Popen(f'cp ./tmp/notes.tmp /tmp/{timestamp}', shell=True)
 ```

 ______________________________

 backup_notes 페이지에서 post 요청을 할 때를 봐볼께요.  
 백업 페이지에 접근하려하면 우선 백업 할 note가 있는지 확인하고 없다면 404 error를 띄워요.  
 후에 timestamp 함수로 쿠키를 생성하고 해당 값을 인자로서 backup_notes() 함수에 보내요.

 ```python
 @app.route('/backup_notes', methods=['POST'])
def post_backup_notes():
    if len(notes) == 0:
        abort(404)
    backup_timestamp = request.cookies.get('backup-timestamp', f'{time.time()}')
    if not isinstance(backup_timestamp, str):
        abort(400)
    backup_notes(backup_timestamp)
    return redirect(url_for('get_index'))
 ```

______________________________

문제는 backup_notes 함수가 실행 될 때예요.  
해당 코드를 보면 subcategory.Popen으로 shell 명령어를 실행 시키고 있는데 옵션을 보면 **shell=True**로 되어 있어요.  
즉, 쉘 코드를 입력하면 실행이 된다는 얘기예요.

 ```python  
 def backup_notes(timestamp):
    with lock:
        with open('./tmp/notes.tmp', 'w') as f:
            f.write(repr(notes))
        subprocess.Popen(f'cp ./tmp/notes.tmp /tmp/{timestamp}', shell=True)
 ```
