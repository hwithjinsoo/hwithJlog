## Payload
accounts 변수를 보면 admin과 guest의 로그인 정보가 존재한다.  
guest는 pw까지 줬는데 admin은 pw가 "FLAG"라는 정보가 다임.     
그치만 FLAG를 직접 찾고 그걸 pw에 넣어 admin으로 로그인하는 문제는 아니다.  

```javascript
const accounts = {
    'admin': {
        'password': FLAG
    },
    'guest': {
        'password': 'guest'
    }
};
```


 취약점은 바로바로 여기에 있어요.
verificationKey() 내부를 들여다보면,  
로그인 할 때 생성되는 토큰을 디코딩 한 뒤 헤더를 가져와  
어떤 알고리즘으로 jwt 서명 했는지 확인하는 로직이에요.  
근데!!! 자세히 들여다보면 암호화 알고리즘으로 RS256과 HS256를 동시에 사용하고 있는게 보여요.    
바로 여기가 취약점이자 인증 우회가 가능한 지점에요.  
아래에서 HS256과 RS256에 대해 조금 더 자세히 봐보겠습니다

```javascript
function verifyToken(token) {
    try {
        const alg = jwt.decode(token, { complete: true }).header.alg;
        if (alg === 'RS256') {
            return jwt.verify(token, verificationKey);
        } else if (alg === 'HS256') {
            return jwt.verify(token, verificationKey, { algorithms: ['HS256'] });
        } else if (alg === 'ES256') {
            return jwt.verify(token, verificationKey, { algorithms: ['ES256'] });
        } else {
            return false;
        }
    } catch (error) {
        return false;
    }
}
```
### JWT란?
> JWT(Json Web Token)는 JSON의 형태로서 로그인 상태를 유지하기 위해  
서버측에 나를 인증하는 신분증 같은거에요    
JSON = Header.Payload.signature 형태를 가지고 있어요  
 
 ### alg 특성
>HS256은 공개키로 암호화 공개키로 복호화     
RS256은 공개키로 암호화 개인키로 복호화

위 특성을 이용하면 guest로 로그인을 해서 인증 우회를 하고 결국 admin 권한을 얻을 수 있어요  
먼저 코드를 살펴보면 헤더의 들어간 알고리즘이 HS256이거나 RS256일 때 jwt 서명을 하고 있어요  
그렇다면 guest로 로그인해서 인증 된 토큰을 두 개 정도 얻어서 "*rsa_sign2n" 프로그램에 넣고 돌리면  
공개키를 얻을 수 있어요
