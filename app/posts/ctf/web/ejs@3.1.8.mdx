## Challenge Analysis
이번 문제의 제목은 ejs@3.1.8입니다. 때문에 ejs가 3.1.8 버전일 때 생겼던 취약점이 있을꺼고

사용자에게 req.query를 받아 그대로 템플릿으로 넘겨주고 있어요.

```javascript

   res.render('index', req.query )
})
```

ejs 3.1.8 버전의 일부 코드에요.  
```javascript

Template.prototype.compile = function () {
  var src;
  var fn;
  var opts = this.opts;
  var prepended = '';
  var appended = '';
  var escapeFn = opts.escapeFunction;

  if (!this.source) {
    this.generateSource();
    prepended += '  var __output = "";\n' +
        '  function __append(s) { if (s !== undefined && s !== null) __output += s; }\n';
    if (opts.outputFunctionName) {
      // 해당 옵션에 대한 검증 로직이 추가 됐어요. 위에서 시도한 페이로드가 먹히지 않은 이유에요.
      if (!_JS_IDENTIFIER.test(opts.outputFunctionName)) {
        throw new Error('outputFunctionName is not a valid JS identifier.');
      }
      prepended += '  var ' + opts.outputFunctionName + ' = __append;' + '\n';
    }
    this.source = prepended + this.source + appended;
  }

  if (opts.client) {
    src = 'escapeFn = escapeFn || ' + escapeFn.toString() + ';' + '\n';
    if (opts.compileDebug) {
      src = 'rethrow = rethrow || ' +
        rethrow.toString() + ';' + '\n' + src;
    }
  }

  src += this.source;
}
```
______________________________

코드를 살펴 보던 중 **outputFunctionName**에서 취약했었던 로직과 비슷하게  
입력받은 구문을 검증하지 않는 백터를 발견했어요.

escapeFn에 들어있는 문자열에 toString()를 적용하기 떄문에  
사용자가 입력한 값이 그대로 들어가요.
```javascript

var escapeFn = opts.escapeFunction;

  if (opts.client) {
    src = 'escapeFn = escapeFn || ' + escapeFn.toString() + ';' + '\n';

```
