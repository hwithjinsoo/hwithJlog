```http
FTP {
    HTTP랑 차이점
    HTTP는 Export Objects로 깔끔하게 추출되는데 FTP는 가끔 Follow TCP Stream으로 raw 데이터 직접 뽑아야 하는 경우 있어.

    ftp 필터
    → 명령 채널에서 로그인 정보, 어떤 파일 주고받았는지 확인

    ftp-data 필터
    → 실제 파일 내용 확인
    → Follow TCP Stream 하면 파일 내용 그대로 보여
}

DNS Tunneling {
    dns 필터 걸고
    → 쿼리 도메인 길이 확인
    → 비정상적으로 긴 서브도메인 있으면 의심
    → 같은 도메인으로 쿼리가 엄청 많으면 의심

    dns.qry.name 필드에서 서브도메인 부분만 뽑기
    → base64 디코딩
    → 데이터 복원
}

icmp Tunneling {
    icmp && data
}

c2 통신 분석 {
    Statistics > Conversations
    → 외부 IP랑 통신 많은 거 식별
    → 비정상 포트 확인 (4444, 1337, 8888 같은 거)
    → 해당 IP 필터링해서 Follow Stream

    # 비정상 포트 필터링
    tcp.port == 4444
    tcp.port == 1337

    # 특정 외부 IP 필터링
    ip.addr == 공격자IP

    # 주기적 비콘 탐지 (같은 IP 통신만)
    ip.dst == 공격자IP

    # HTTP로 위장한 C2 (User-Agent 확인)
    http.user_agent

    리버스 쉘 {
        Follow TCP Stream 하면 이런 게 보여:
        whoami
        root
        ls -al
        flag.txt  secret.zip  ...
        cat flag.txt
        flag{reverse_shell_found}
    }

    비콘 신호 {
        0.000s  192.168.1.100 → attacker.com
        60.000s 192.168.1.100 → attacker.com
        120.000s 192.168.1.100 → attacker.com
    }

    http 위장 {
        GET /update HTTP/1.1
        User-Agent: Mozilla/5.0 aGVsbG8gd29ybGQ= << user-Ageng에 base64 데이터 숨기기.
    }

    http 필터 {
        http.request.uri contains ""
    }

}

파일 복원 {
    File > Export Objects > HTTP
    File > Export Objects > FTP-DATA
    File > Export Objects > SMB
        목록에서 파일 선택 후 save

    수상한 패킷 우클릭
    → Follow TCP Stream
    → Show data as: Raw
    → Save As로 저장
    → file 명령어로 실제 포맷 확인
    → 확장자 맞게 바꾸기

    HTTP로 전송된 이미지/zip 복원 → 안에 flag
    FTP로 전송된 파일 복원
    복원한 파일이 이미지면 → 이미지 포렌식으로 연결
    복원한 파일이 zip이면 → 비밀번호 찾기로 연결
}

접근 순서 정리 {
    1. Statistics > Protocol Hierarchy
    어떤 프로토콜이 주로 쓰였는지 파악. 분석 방향 결정.

    2. Statistics > Conversations
    어떤 IP끼리 통신했는지 파악. 수상한 IP 식별.

    3. 프로토콜 필터링
    파악한 프로토콜 기준으로 필터 걸기.
    http, ftp, dns, icmp 순으로 확인.

    4. Follow Stream
    수상한 패킷 우클릭 → Follow TCP/UDP/HTTP Stream.
    주고받은 데이터 전체 확인.
    인코딩된 데이터 보이면 CyberChef로 디코딩.

    5. Export Objects
    File > Export Objects > HTTP/FTP-DATA
    파일 전송 흔적 있으면 여기서 추출.
    추출한 파일이 이미지면 이미지 포렌식으로 연결.

    이미지 포렌식이랑 다르게 pcap은 프로토콜 파악이 먼저야. 거기서 방향이 결정되거든.
}
```

## sysmon
```html
Event ID 1 (Process Create) - "이 프로세스가 무슨 명령어로 실행됐지?"

방금처럼 SysmonView에서 의심스러운 cmd.exe를 발견했을 때, 그 cmd가 정확히 어떤 명령어(CommandLine)로, 누구(Parent)에 의해, 어떤 권한(User)으로 실행됐는지 확인. 예: GitStack에서 SYSTEM 권한으로 cmd.exe가 실행된 걸 발견 → Event ID 1로 어떤 명령어였는지 확인.
Event ID 3 (Network Connection) - "이 프로세스가 외부랑 통신했나?"

악성 프로세스(예: powershell.exe)를 찾았는데, 얘가 인터넷으로 뭔가 보냈는지 궁금할 때. 예: powershell이 실행된 직후 같은 PID가 외부 IP 1.2.3.4의 4444번 포트로 연결한 Event ID 3이 있다면 → C2 서버 통신 흔적. "탈취한 데이터를 어디로 보냈나" 문제에서 핵심.
Event ID 5 (Process Terminated) - "이 프로세스가 언제 끝났지?"

실행 시간이 너무 짧은(1초 이내) 프로세스를 찾을 때 시작-종료 시간을 대조. 예: cmd.exe가 3:32:45에 생성되고 3:32:45에 바로 종료 → 명령어 하나 실행하고 즉시 끝나는 일회성 익스플로잇 패턴 확인용.
Event ID 7 (Image/DLL Loaded) - "이 프로세스에 이상한 DLL이 로드됐나?"

정상 프로세스(explorer.exe 등)가 시스템 경로가 아닌 temp 폴더의 DLL을 로드했다면 DLL 사이드로딩/인젝션 의심. 예: "악성코드가 어떻게 은신했나" 문제에서 사용.
Event ID 8 (CreateRemoteThread) - "한 프로세스가 다른 프로세스에 코드를 주입했나?"

프로세스 인젝션 탐지. 예: notepad.exe 같은 정상 프로세스 안에 svchost.exe가 스레드를 주입한 이벤트 발견 → 악성코드가 정상 프로세스로 위장(프로세스 할로잉 등).
Event ID 10 (ProcessAccess) - "누가 lsass.exe 메모리에 접근했나?"

계정 탈취/자격증명 덤프 시나리오. 예: lsass.exe(SourceImage가 아니라 TargetImage가 lsass.exe)에 알 수 없는 프로세스가 접근한 Event ID 10 발견 → mimikatz 같은 도구로 비밀번호 해시 추출 시도.
Event ID 11 (File Create) - "공격자가 어떤 파일을 떨어뜨렸나?"

악성 파일 드롭 확인. 예: temp 폴더에 .exe나 .dll이 생성된 시점을 찾아서 그 파일이 뭔지(이름, 경로) 확인 → 멀웨어 샘플 위치 파악.
Event ID 12/13/14 (Registry Event) - "공격자가 재부팅해도 살아남게 설정했나?"

지속성(Persistence) 확인. 예: Run 키(HKCU\...\Run)에 새 값이 추가된 레지스트리 이벤트 발견 → 시작 시 자동 실행되는 악성 프로그램 등록 흔적.
Event ID 22 (DNS Query) - "이 프로세스가 어떤 도메인을 조회했나?"

C2 도메인 확인. 예: powershell.exe가 evil-c2.com을 DNS 조회한 기록 → 그 도메인이 공격자 서버.
Event ID 23 (File Delete) - "공격자가 흔적을 지웠나?"

안티포렌식 확인. 예: 악성 파일을 실행 직후 같은 파일을 삭제하는 Event ID 23 발견 → 흔적 은폐 시도.
Security 로그 4624/4625 - "누가 로그인 성공/실패했나?"

계정 탈취 문제에서 "어떤 계정이 언제 로그인했나" 확인. 예: 새벽 시간대에 평소 안 쓰던 계정으로 4624(성공) 로그가 있다면 → 탈취된 계정으로 로그인한 시점.
지금 풀고 있는 게 "계정 탈취" 시나리오라고 했으니까, 1번으로 침투 경로 확인한 다음엔 10번(lsass 접근)이나 4624(로그온)를 봐야 할 가능성이 높아. 로그에 그런 이벤트가 있는지 한번 찾아볼래?

```

```html
SysmonView에서 의심스러운 exe 박스를 찾았으면, 더 자세히 보는 방법 몇 가지:
1. 박스 더블클릭 / 우클릭

박스를 더블클릭하거나 우클릭하면 컨텍스트 메뉴가 뜨는데, 보통 "View Event Details" 같은 옵션으로 해당 프로세스의 Event ID 1 상세 정보(Image, CommandLine, ParentCommandLine, User, Hash 등)를 바로 보여줘. 방금 본 ProcessCreate Event Details 창이 이 방식으로 뜬 거야.
2. 해시값으로 VirusTotal 조회

상세 정보 화면에 MD5/SHA1/SHA256 해시랑 VirusTotal 체크박스가 있었지? 해시를 복사해서 VirusTotal에 넣으면 이 파일이 알려진 악성코드인지, 탐지율이 얼마인지 바로 확인 가능. 다만 대회 환경(인터넷 차단)이면 이건 안 될 수도 있음.
3. Process GUID로 연관 이벤트 추적

상세 정보에 나온 Process GUID(예: {6B166207-60B9-5BFF-0000-001...})를 복사해서, 이벤트 뷰어에서 같은 GUID를 가진 다른 이벤트들(Event ID 3, 5, 7, 11 등)을 검색 - 그러면 이 프로세스가 생성된 이후 뭘 했는지(네트워크 연결, 파일 생성, 종료 시점 등) 전부 추적 가능.
4. Map View에서 좌우로 확장

의심 exe 박스 주변에 다른 부모/자식 프로세스가 더 있는지 트리를 확장해서 확인 - 화면에 안 보이던 추가 프로세스가 연결되어 있을 수 있음.
5. All Events View 탭 활용

화면 상단에 "All Events View" 탭이 있었지? 거기서 특정 Image 경로나 시간대로 필터링하면, Map View에서 안 보이는 다른 이벤트 타입(파일 생성, 네트워크 등)까지 한 번에 검색 가능.
지금 새로 찾은 의심스러운 exe가 뭐야? 어떤 경로/이름인지 알려주면 어디부터 볼지 같이 짚어볼게.
```

```html
웹 (Web)
문제 보면 일단 페이지 소스 보기부터. 주석에 힌트 숨겨놓는 경우 진짜 많아. 그리고 robots.txt, sitemap.xml, .git 폴더 노출 여부 항상 체크해.
쿠키 확인은 필수. 세션 쿠키가 base64나 JWT 형태면 디코딩해서 구조 파악하고, 알고리즘이 none이거나 서명 검증이 약하면 변조 시도.
SQLi는 ' 하나 넣어서 에러 메시지부터 확인. 에러 기반이면 UNION SELECT 컬럼 수 맞추는 게 첫 단계고, 필터링이 있으면 대소문자 섞기, 주석 처리(/**/), 인코딩 우회 시도.
파일 업로드 문제면 확장자 필터 우회(대소문자, 이중확장자, null byte), Content-Type 변조, 매직바이트 추가해서 검사 통과시키는 거 생각해봐.
SSRF/LFI는 파라미터에 file://, php://filter, 내부 IP(127.0.0.1, localhost, 169.254.169.254 클라우드 메타데이터) 넣어보기.
명령어 삽입은 ;, |, &&, $(), 백틱 등으로 시도하고, 필터링되면 공백 대신 ${IFS}나 ${IFS}$9 같은 우회법 떠올려봐.
응답이 안 보이는 블라인드 상황이면 시간 지연(sleep)으로 참/거짓 판단하거나, 에러를 응답 헤더/타이밍 차이로 추론.
소스코드가 주어지면 반드시 읽어. 어디서 사용자 입력을 받고 어디로 흘러가는지(데이터 흐름) 따라가면 취약점 위치가 보여. 필터링 로직이 있다면 그 로직의 빈틈(정규식 우회, 인코딩, 대소문자)을 찾는 게 핵심.
포렌식 (Forensics)
파일 받으면 file 명령어로 진짜 파일 타입부터 확인. 확장자랑 실제 시그니처(매직바이트)가 다른 경우 많아.
이미지 파일이면: exiftool로 메타데이터 먼저, 그다음 binwalk로 숨겨진 파일 있는지, strings로 텍스트 추출, 그리고 LSB 스테가노그래피 의심되면 stegsolve나 zsteg.
zip 구조인 파일(docx, odt, pptx, jar 등)이면 압축 풀어서 내부 xml/리소스 파일 뒤지기. 의심되면 확장자를 .zip으로 바꿔서 열어보면 됨.
pcap 파일이면 Wireshark에서 "Follow TCP Stream"으로 대화 흐름 보고, File > Export Objects로 HTTP/FTP로 전송된 파일 추출. DNS/ICMP 터널링 의심되면 같은 도메인이나 같은 길이의 패킷이 반복되는지 통계(Statistics > Conversations)로 확인.
평문 자격증명은 HTTP Basic Auth, FTP, Telnet 같은 암호화 안 된 프로토콜에서 자주 나와 - Wireshark 필터에 ftp, http.authorization, telnet 걸어서 찾아봐.
메모리 덤프(memdump)면 volatility 같은 도구로 프로세스 목록, 네트워크 연결, 명령어 히스토리 추출하는 흐름.
파일이 암호화/난독화된 것 같으면 base64, hex, rot13, xor 순서로 시도해보고, 반복되는 패턴이 보이면 xor 키 길이 추정 가능.
위협 침해 분석 (Threat Hunting / Incident Response)
오늘 다룬대로 시간순으로 따라가는 게 핵심. SysmonView나 비슷한 도구로 프로세스 트리에서 비정상적인 부모-자식 관계(예: word.exe → cmd.exe → powershell.exe, 또는 웹서버 프로세스 → cmd.exe)부터 찾아.
타임라인을 만들어. 첫 침투 시각, 권한 상승 시각, 데이터 유출 시각 순서대로 정리하면 "공격 스토리"가 보이고, 문제에서 묻는 답(어떤 계정, 어떤 IP, 어떤 시각)이 자연스럽게 나와.
Event ID 1(프로세스 생성)에서 CommandLine 필드는 거의 항상 핵심. powershell -enc(base64 인코딩 명령어), certutil(파일 다운로드 악용), wmic, rundll32 같은 LOLBin(Living off the land binary)이 보이면 의심.
네트워크 연결(Event ID 3)에서 평소 안 쓰는 외부 IP나 비표준 포트(4444, 8080, 1337 등) 찾기 - C2 서버일 가능성.
자격증명 탈취 의심되면 lsass.exe에 대한 ProcessAccess(Event ID 10) 확인, 그리고 Security 로그에서 4624(로그온 성공)를 시간대별로 정렬해서 평소와 다른 시간/계정의 로그온 찾기.
```
